# Evals

Синтетические задания для проверки поведения агента и API на эталонных сценариях.

## Структура

| Каталог | Назначение |
|---|---|
| `tasks/` | входные задания: сообщение пользователя, контекст, ожидаемые вызовы инструментов |
| `expected/` | эталоны: ожидаемое состояние заявки, ответ и события |
| `runs/` | результаты прогонов (содержимое не коммитится, кроме `.gitkeep`) |

## Формат задания

```json
{
  "id": "001-happy-path",
  "description": "Сотрудник просит доступ к системе аналитики",
  "input": {
    "message": "Нужен доступ к дашбордам аналитики на неделю",
    "user_id": "u-1"
  },
  "expected": {
    "state": "submitted",
    "tool_calls": ["search_system", "get_access_policy", "create_access_request"]
  }
}
```

## План

1. Согласовать сценарии с [`specs/access-request.md`](../specs/access-request.md),
   включая негативные случаи.
2. Добавить runner (Python или Go), который прогоняет задания против staging API.
3. Сравнивать состояние заявки, состав вызовов инструментов и события из
   [`docs/metrics.md`](../docs/metrics.md).
4. Сохранять результаты в `runs/<date>/` и прикладывать к отчёту покрытия сценариев.
