# PRD — Avito AI Buddy

> Статус: черновик. Первый коммит фиксирует каркас проекта; домен, scope и метрики
> требуют подтверждения у продукта.

## 1. Цель

Сократить время и количество ошибок при оформлении заявок на доступ к внутренним
системам: AI-бадди собирает недостающие данные, проверяет политику доступа,
формирует заявку и передаёт её ответственному.

## 2. Аудитория

| Роль | Потребность |
|---|---|
| Сотрудник | Быстро получить нужный доступ, не разбираясь в процедурах |
| Ответственный за доступы | Получать полные и валидные заявки |
| Поддержка / ИБ | Видеть историю решений и причины отказов |

## 4. Пользовательский путь

1. Сотрудник открывает веб-интерфейс и описывает, какой доступ ему нужен.
2. Агент уточняет систему, роль и обоснование, сверяясь с политикой.
3. Агент показывает черновик заявки, сотрудник подтверждает отправку.
4. Заявка уходит ответственному; сотрудник видит её статус.
5. При отказе агент объясняет причину и предлагает следующий шаг.

Детали поведения — в [`specs/access-request.md`](../specs/access-request.md).

## 5. Критерии приёмки

- [ ] `docker compose up` поднимает frontend, backend, PostgreSQL и Redis
- [ ] `/readyz` возвращает `200`, когда зависимости доступны, и `503` иначе
- [ ] заявка не создаётся при отсутствии обязательных полей
- [ ] каждое действие агента порождает событие из [`docs/metrics.md`](metrics.md)
- [ ] синтетические сценарии из `evals/` проходят на staging
