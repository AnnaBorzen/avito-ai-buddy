## Контракт документа

Каждый файл начинается YAML front-matter с полями:

| Поле | Обязательно | Правило |
|---|---|---|
| `doc_id` | да | совпадает с именем файла без `.md` |
| `title` | да | начинается с маркера `[ТЕСТОВАЯ ИНСТРУКЦИЯ]`; для закрытых — `[ТЕСТОВАЯ ИНСТРУКЦИЯ - ЗАКРЫТЫЙ ДОКУМЕНТ]` |
| `allowed_roles` | да | непустой список ролей |
| `allowed_teams` | да | `["*"]` или список `team_id` |
| `is_synthetic` | да | `true` (документы не являются регламентом Авито) |

Фильтрация по `allowed_roles`/`allowed_teams` выполняется **до** поиска и до
передачи контекста в LLM; правила — [`../specs/access-request.md`](../specs/access-request.md) §8.

## Почему маркеры обязательны

`title` уходит в ответ API (`Source.title`), а интерфейс показывает по нему
бейдж «Тестовая инструкция» (FR-02). Документ без маркера нарушает FR-02 и не
проходит eval. Закрытый `doc_03` не должен попадать ни в выдачу, ни в ответ
стажёру, ни в аналитику.

## Правила правки

1. Менять текст можно только вместе с правкой §9 ТЗ; иначе это второй источник
   истины.
2. Нельзя смягчать запреты (`ЗАПРЕЩЁН`, `ТОЛЬКО на уровне read`) — на них
   опираются AC-02 и политика доступа.
3. Срок «до 4 рабочих часов» и `pending` цитируются из `doc_01`, а не хардкодятся
   в коде.
4. Контрольный вопрос AC-05 («VPN на личном смартфоне…») должен оставаться без
   ответа в корпусе: не добавлять документ с этой процедурой.
