# Сервисы и зоны ответственности

## 1. Границы

| Компонент | Владеет | Не владеет |
|---|---|---|
| `frontend` | отображение состояний (§4 ТЗ), карточка, переключатель профиля | права, валидация, идемпотентность |
| `backend-api` | контекст, диалог, RBAC, черновик, подтверждение, сохранение результата, события | содержимое заявки после создания (владелец — сервис доступов) |
| `access-service mock` | заявка и её `external_status` | роли и права пользователей |
| RAG-корпус (`rag_docs/`) | текст синтетических инструкций и их маркеры | решение о доступности документа (его принимает `Knowledge` по фильтру) |

Всё, что относится к собственному домену AI-buddy (сценарий, операция, политика,
аналитика), остаётся модулями внутри `backend-api`: отдельные сервисы под это не
выделяются — MVP не имеет независимых причин масштабирования.

## 2. Что имитируем и почему

| Внешняя система | Почему имитация | Что фиксируем в контракте |
|---|---|---|
| Сервис доступов (заявки) | нет доступа к реальному корпоративному сервису | [`access-service.openapi.yaml`](../../contracts/access-service.openapi.yaml) |
| База знаний (Confluence-подобная) | корпус синтетический по §9 ТЗ | front-matter документов + `Source` в API |
| Провайдер LLM | демонстрация не должна зависеть от сети | `contracts/mcp-tools.yaml`, детерминированный провайдер |
| SSO | §10 ТЗ заменяет его заголовком профиля | [`05-auth.md`](05-auth.md) |

Имитация обязана вести себя как владелец данных: хранить заявку между запросами,
возвращать её по `operation_id`, поддерживать демонстрационные сбои
(`X-Simulate-Mode`).

## 3. Синхронные взаимодействия

| Вызов | Таймаут | Поведение при сбое |
|---|---|---|
| `POST /chat/messages` → LLM | 30 с | 504 `UPSTREAM_TIMEOUT`, карточка не создаётся, повторяемо |
| `POST /operations/{id}/confirm` → сервис доступов | 10 с | 504 + `unknown` (запрос мог дойти) |
| `POST /operations/{id}/reconcile` → сервис доступов | 5 с | статус остаётся `unknown` |
| `GET /context` → БД/кэш | 1 с | 500 `INTERNAL_ERROR`, ретрай клиента |

Таймауты — параметры конфигурации backend, а не контракта: контракт фиксирует
результат (какой статус и какой код ошибки), не длительность.

## 4. Две реализации одного контракта

| Реализация | Роль | Ограничения |
|---|---|---|
| `frontend/server/*.mjs` (демо-макет на middleware Vite, `node:sqlite`) | быстрая демонстрация сценария без сборки Go | одна нода, без горизонтального масштабирования; обязан повторять `contracts/api.yaml` |
| `backend/internal` (Go) | целевая реализация прототипа | сейчас только `/healthz`, `/readyz` |

Переключение демо-режима — переменная `VITE_USE_MOCK_API` во фронтенде. Когда
Go-backend реализует контракт, макет выключается без изменения контракта и
спецификации.

## 5. Хранение

| Хранилище | Что | Владелец |
|---|---|---|
| PostgreSQL 17 | операции, заявки, записи идемпотентности, события аналитики | `backend-api` |
| Redis 7.4 | кэш профилей и справочника команд (read-through) | `backend-api` |
| `node:sqlite` (только демо) | то же для демо-макета | демо-макет |
| Файлы `rag_docs/*.md` | синтетические документы | репозиторий (версионируются вместе с кодом) |

Никакой другой компонент не пишет в эти хранилища напрямую: чтение чужих таблиц
и файлов скрыто за адаптерами.
