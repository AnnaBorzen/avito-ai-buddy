# Версионирование API и контракт-первый

## 1. Стратегия

- Все пользовательские эндпоинты — под префиксом `/api/v1` (§10 ТЗ). Служебные
  `/healthz`, `/readyz` — вне префикса.
- Внутри `v1` допустимы только аддитивные изменения: новые необязательные поля,
  новые значения enum только там, где клиент обязан игнорировать неизвестное,
  новые эндпоинты.
- Breaking-изменения (переименование/удаление поля, смена типа, новое
  обязательное поле, изменение смысла статуса) требуют `v2`.
- Внутренний контракт сервиса-имитации (`/internal/*`) версионируется вместе с
  `contracts/access-service.openapi.yaml`; наружу он не публикуется.

## 2. Порядок изменения (SDD, §5 ТЗ)

1. Правка `contracts/*.yaml` и спецификации поведения
   ([`specs/access-request.md`](../../specs/access-request.md)).
2. Проверка по [`08-validation-checklist.md`](08-validation-checklist.md).
3. Реализация в `backend/internal` (или демо-макете) и тесты на инварианты.
4. Обновление README/PRD, если изменилось поведение для пользователя.

Изменение кода без шага 1 считается дефектом процесса: контракт — источник
истины для обеих реализаций (AD-10).

## 3. Совместимость enum-ов

| Enum | Клиент обязан | Комментарий |
|---|---|---|
| `StepStatus` | отображать неизвестное значение как «в процессе», не падать | добавление `blocked` уже произошло |
| `OperationStatus` | явная обработка всех 6 значений; неизвестное → состояние ошибки | новый статус — breaking |
| `TicketStatus` | отображать любое значение из контракта, не только `pending` | `approved`/`rejected` ещё не возвращаются имитацией |
| `ErrorCode` | неизвестный код → общий текст ошибки + лог | расширение каталога аддитивно |

## 4. Тексты и копирайт

Формулировки статусов («заявка создана», «ожидает согласования», «доступ ещё не
активирован») — часть контракта поведения, а не свободный текст UI: они
проверяются тестами (INV-05). `pending` не может быть назван выданным доступом
ни в одном состоянии.

## 5. Расширения

Всё, чего нет в §10 ТЗ, помечено `x-extensions` в
[`contracts/api.yaml`](../../contracts/api.yaml) и перечислено в
[спеке §15](../../specs/access-request.md). Расширение не должно ломать клиента,
написанного строго по §10: клиент вправе игнорировать неизвестные поля.
