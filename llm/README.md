# LLM-слой: промпты, скиллы, MCP

Артефакты разработки AI-сценария по подходу SDD. Спецификации, по которым они написаны:
[`specs/access-request.md`](../specs/access-request.md) (поведение агента) и
[`specs/ml-agent.md`](../specs/ml-agent.md) (ML-часть).

| Каталог | Назначение |
|---|---|
| [`prompts/`](prompts) | системный промпт агента (канонический файл лежит в образе ML-сервиса) |
| [`skills/`](skills) | переиспользуемые скиллы агента: сбор полей заявки, проверка политики, ответ по базе знаний |
| [`mcp/`](mcp) | MCP-сервер инструментов и пример конфигурации подключения |

## Как это используется

- **ML-сервис** (`ml/`) собирает промпт из [`ml/buddy_ml/prompts/system_ru.md`](../ml/buddy_ml/prompts/system_ru.md),
  подставляя доверенный контекст из запроса backend, и передаёт LLM схему `propose_access_request`
  ([`ml/buddy_ml/tools.py`](../ml/buddy_ml/tools.py)).
- **Платформа ИИ-агентов** (если сценарий переносится туда) подключает MCP-сервер
  [`ml/buddy_ml/mcp_server.py`](../ml/buddy_ml/mcp_server.py) и скиллы из `skills/` как инструкции агента.
- Инструмента отправки заявки нет ни в function calling, ни в MCP: отправка — только по подтверждению в UI.
