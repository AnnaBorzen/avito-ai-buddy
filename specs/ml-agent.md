# SDD: ML-часть AI-buddy

**Статус:** Accepted · **Код:** [`ml/`](../ml) · **Поведение агента:** [`specs/access-request.md`](access-request.md) ·
**API:** [`contracts/ml-api.yaml`](../contracts/ml-api.yaml) · **Отчёты:** [`evals/reports/`](../evals/reports)

## 1. Задачи ML по ТЗ

| Требование | Что делает ML | Где |
|---|---|---|
| FR-01 контекст стажёра | ответы и примеры строятся из доверенного `user`/`permissions` | `agent.py` |
| FR-02 ответ по материалам | RAG с ACL до ранжирования, источники с бейджами | `retrieval.py`, `knowledge.py` |
| FR-03 недостаток информации | уточнение параметров / честный отказ + наставник | `agent.py`, `nlu.py` |
| FR-05 подтверждение | у агента только `propose_access_request` (черновик) | `tools.py` |
| Метрики RAG Faithfulness, Tool Accuracy | офлайн-evals с порогами приёмки | `evaluation.py`, `scripts/run_evals.py` |
| Защита от prompt injection | детектор, санитизация документов, проверки ответа | `guard.py` |

## 2. Архитектура

```
 Browser ──► Backend (Go)  ── POST /v1/agent/turn ──►  ML service (Python, Flask, stateless)
             session, RBAC,                            │
             operations, DB      ◄── reply, sources, ──┤ 1. guard.detect_injection   (regex-паттерны атак)
             confirm/idempotency     slots, tool_call  │ 2. nlu: интент (TF-IDF + LogReg) + слоты (правила + fuzzy)
                                                       │ 3. route: атака → отказ; вне каталога → no_data; заявка → слоты…
                                                       │ 4. retrieval: ACL-фильтр → BM25 по стемам (+опц. dense) → покрытие
                                                       │ 5. policy.check (консультативный RBAC по permissions от backend)
                                                       │ 6. ответ: шаблон + извлечённый фрагмент   ─ или ─
                                                       │    LLM (function calling) → валидация → guard ответа → fallback
                                                       └ knowledge/: тестовые инструкции, чек-лист кейса, Playbook (опц.)
```

Почему отдельный сервис, а не код в Go: стек Авито допускает Python/Flask «в отдельных случаях» — ML как раз
такой случай (sklearn, стемминг, эмбеддинги, eval-инструменты). Сервис stateless, поэтому состояние,
идемпотентность и права остаются в одном месте — в backend. Для платформы ИИ-агентов те же инструменты
доступны через MCP ([`ml/buddy_ml/mcp_server.py`](../ml/buddy_ml/mcp_server.py)).

| Корпус | Документы | Доступ | Метка в UI |
|---|---|---|---|
| Синтетические инструкции из ТЗ (`ml/knowledge/synthetic`) | doc_01, doc_02 — всем; doc_03 — только `lead` команды Auto | ACL из front matter | «Тестовая инструкция» |
| Чек-лист стажёра из материалов кейса (`ml/knowledge/case_materials`, скрипт `build_checklist_docs.py`) | doc_04 общий, doc_05 Backend, doc_06 — пункты для наставника (только `mentor`/`lead`) | ACL | «Материал кейса» |

Документ без `allowed_roles` закрыт для всех (secure by default). Playbook не коммитится (в репозитории нет
лицензии) — скачивается при сборке образа; без сети сервис работает на первых двух корпусах.

## 4. Модели и решения

### 4.1 Поиск: выбран BM25 по русским стемам — по результатам измерений

Сравнение на `evals/tasks/retrieval.jsonl` (64 размеченных запроса, из них 6 с опечатками, 3 проверки утечек),
корпус 680 фрагментов, CPU ([полный отчёт](../evals/reports/retrieval_comparison.md)):

| Конфигурация | Recall@1 | Recall@3 | MRR@5 | мс/запрос |
|---|---|---|---|---|
| **BM25 (по умолчанию)** | **0.891** | **0.953** | **0.922** | **1.1** |
| BM25 + TF-IDF (символьные n-граммы) | 0.875 | 0.953 | 0.914 | 6.2 |
| dense `rubert-tiny2` | 0.406 | 0.609 | 0.520 | 6.3 |
| dense `multilingual-e5-small` | 0.797 | 0.859 | 0.833 | 21.1 |
| BM25 + TF-IDF + e5-small (RRF) | 0.844 | 0.953 | 0.894 | 34.7 |

Корпус небольшой и терминологичный (`space_auto_backend_wiki`, «согласование», «SPT»), поэтому точное
совпадение стемов выигрывает; dense-модели не дали прироста ни по одной метрике, а стоят +~2 ГБ образа (torch)
и в 20–30 раз большей задержки. Dense и TF-IDF оставлены как опции (`ML_RETRIEVER`, `WITH_DENSE=1`) — их стоит
перепроверить тем же скриптом при росте корпуса и доле перефразированных вопросов.

**ACL до ранжирования:** скоринг считается только по строкам индекса, разрешённым пользователю; закрытые
фрагменты не участвуют даже в нормировке (утечки в выдаче — 0 во всех конфигурациях).

**Уверенность для отказа:** IDF-взвешенное покрытие терминов запроса найденным фрагментом. Термин, которого
нет в корпусе, получает максимальный вес — вопрос про «VPN на iPhone» или «курс доллара» получает низкую
уверенность. Дополнительно OOV-доля запроса относительно *доступных* пользователю документов (термины
закрытого документа для стажёра считаются неизвестными — нет побочного канала).

### 4.2 Интент: TF-IDF + логистическая регрессия

12 интентов, 371 синтетическая реплика (`nlu_data.py`, 15–60 на интент), признаки: стемы 1-2-граммы + символьные 2–5-граммы,
`class_weight=balanced`. Обучение при старте < 1 с, детерминированно (seed) — нет бинарных артефактов.
Отложенная выборка (51 реплика, не пересекается с обучающей — проверяет тест): **accuracy 98.0 %, macro-F1 0.983**.
Выбор против дообучения трансформера: на синтетике размер модели не ограничивает качество, а
латентность ~1 мс и отсутствие GPU/torch важнее; при появлении реальных обращений — переразметка и замер.

### 4.3 Слоты: правила + нечёткое сопоставление

Ресурс — алиасы с приоритетом (id → prod → чужая вики → репозиторий → своя вики по `team_id`), уровень — явные
слова с обработкой отрицаний («редактировать не нужно, только читать»), обоснование — после маркеров
«для/чтобы/потому что/обоснование:» с фильтром «для записи ≠ обоснование». Опечатки — `difflib` по словарю
ключевых слов. Без явного упоминания уровень/обоснование **не заполняются**.

### 4.4 LLM-режим

Любой OpenAI-совместимый API (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_TIMEOUT`): OpenAI, YandexGPT
(OpenAI-compatible), vLLM/Ollama on-prem. LLM формулирует ответ и может вызвать `propose_access_request`;
валидация и fallback описаны в [`access-request.md` §8](access-request.md#8-llm-режим). По умолчанию LLM
выключен: прототип полностью работает без ключа (требование воспроизводимости для экспертов).

## 5. Оценка качества

### 5.1 Протокол

| Набор | Что проверяет | Размер |
|---|---|---|
| `evals/tasks/dialogs.jsonl` | сквозные диалоги: AC-01…AC-05, RBAC, изоляция профилей, инъекции, статусы, план | 49 кейсов / 62 хода |
| `evals/tasks/retrieval.jsonl` | Recall@k/MRR поиска, утечки закрытых документов | 64 запроса |
| `evals/tasks/nlu_holdout.jsonl` | классификатор интентов на отложенных формулировках | 51 реплика |

На **каждом** ходе проверяются инварианты: нет утечки закрытого содержимого и источника, нет ложного
«доступ выдан», нет «регламента Авито». Прогон: `python ml/scripts/run_evals.py` (`--strict` в CI).

### 5.2 Текущие результаты (local-режим, BM25, с Playbook)

| Метрика ТЗ | Значение | Порог |
|---|---|---|
| Tool Accuracy (решение о вызове + аргументы + права) | **100 %** (30 ходов) | ≥ 95 % |
| Отказ «нет данных» (AC-05) precision / recall | 87.5 % / **100 %** | recall ≥ 95 % |
| Устойчивость к prompt injection | **100 %** | 100 % |
| Утечки закрытых документов / ложный успех | **0 / 0** | 0 |
| Доля пройденных ходов | **100 %** | ≥ 90 % |
| Faithfulness-прокси (доля предложений с опорой на источник) | 86.9 % | — (контроль) |
| Латентность хода p50 / p95 | 2.2 / 3.7 мс | UI < 1 с |

Актуальная сводка — [`evals/reports/latest.md`](../evals/reports/latest.md) (генерируется скриптом).

### 5.3 Faithfulness для LLM-режима

Автоматический прокси (лексическая опора каждого предложения на процитированные фрагменты) годится для
регрессии, но не заменяет разметку. Протокол ручной оценки для пилота: 100 случайных ответов `answer`
в неделю, двое разметчиков (Product + ML) по шкале «подтверждено / частично / не подтверждено / противоречит»,
согласованность — каппа Коэна; метрика = доля «подтверждено» среди проверенных ответов; разногласия — разбор.

## 6. Безопасность и данные

- В ML не хранится ничего: нет БД, логов диалогов и ключей на диске. Логируются метод, путь, статус, длительность.
- `LLM_API_KEY` не попадает в `/readyz` и `repr` настроек (тест `test_settings_from_env_and_public`).
- Аналитика получает только метаданные (интент, doc_id, режим, версия сценария) — без текста диалога.
- Пользовательский ввод ограничен 2000 символами, история — 12 сообщениями.

## 7. Ограничения и развитие

- Наборы синтетические и написаны командой → оценки оптимистичны. Для пилота: выгрузка реальных
  обезличенных вопросов стажёров, переразметка, повторный замер тем же раннером.
- Правила слотов покрывают один сценарий; для 3–5 сценариев — LLM-извлечение с той же валидацией «заземлённости».
- Расширение базы: подключение командных пространств через MCP-коннекторы платформы с теми же ACL-полями.
- Онлайн-контроль: доля `no_data` и `handoff` по интентам, доля `local_fallback`, латентность LLM — в Grafana.
